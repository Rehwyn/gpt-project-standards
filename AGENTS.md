# Public Repository Guidelines

This repository is the public distribution surface for Project Standards and reusable skills.

## Content boundary

- Keep only `README.md`, `LICENSE`, this public-safe `AGENTS.md`, the two released standards under `standards/`, and the `project-context-design`, `prompt-design`, and `review-and-change` bundles under `skills/`.
- Do not add private research, reports, notes, archives, migration evidence, personal deployment prompts, local absolute paths, private provenance, real-world personal identity, or personal email addresses.
- Public standards omit private owner metadata. Use `Rehwyn` where a public maintainer identity is necessary.
- Do not import history from a private development repository.

## Authority and changes

- Published standards under `standards/` define the released doctrine in this repository.
- Skills under `skills/` operationalize that doctrine for narrower recurring tasks; preserve their names, triggers, exclusions, references, and interface metadata.
- Preserve published Document IDs, filenames, statuses, versions, links, and license terms unless a release explicitly changes them.
- Substantive doctrine is reconciled through the maintainer’s canonical source before publication. Do not let public-only edits create an unreviewed competing version.

## Verification

- Check personal-information and private-source boundaries before every commit or release.
- Validate Markdown links, headings, final newlines, standard metadata, skill frontmatter, callable references, and source alignment.
- Keep public commits attributable to `Rehwyn` through the approved GitHub noreply address.
- Do not commit, tag, release, or push without explicit authorization.
